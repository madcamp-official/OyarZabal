# V7.5 극단적 Residual scale 실험

## 결론

V7.5는 Residual scale과 확률 안전 cap을 다음처럼 크게 열었다.

```json
{
  "reliabilityScaleBoost": 1.5,
  "contextGatePower": 0.5,
  "fullTierBoost": 6.372873,
  "limitedTierBoost": 6.372873,
  "scaleCap": 4.0,
  "jsDivergenceCap": 1.0,
  "classProbabilityShiftCap": 1.0
}
```

non-zero scale 평균은 V7.4의 0.335에서 V7.5의 1.000으로 약 3배,
p90은 0.5에서 2.469로 약 4.9배가 됐다. 그러나 MLB 전체 Log Loss는
V7.4 `1.135289`에서 V7.5 `1.136717`로 악화됐고, Global-only
`1.136480`보다도 나빴다. 경기 bootstrap의 Global 대비 Log Loss 개선 CI도
`[-0.00100, 0.00043]`으로 0을 포함한다.

실패 원인은 scale 자체보다 tier 차이다. full 3명은 모든 핵심 지표가 크게
개선됐지만 limited 42명은 Macro F1 `−3.62%p`, Log Loss `+0.00389`,
TVD `+8.00%p`로 무너졌다. 따라서 V7.5는 배포 후보가 아니라 “full에는 더
큰 scale 여지가 있지만 limited에 같은 배율을 주면 과보정된다”는 stress
test 결과로 보존한다.

## 평가 설계

- 모델 학습 데이터: 2022–2025, V7.2와 동일
- 평가 기간: 2026-03-25~07-25
- 전체 MLB: 459,530구
- 고정 개인화 cohort: 30명·28,734구
- cohort fingerprint:
  `a2d7de0347b98e9cac05fe1ee22eedc1eab33aa5430e770089755f8945198232`
- 공식 decoder: `family-sum-then-child`
- 2026-07-26 이후 prospective 데이터: 제외

`JS cap=1`은 Jensen–Shannon divergence의 이론적 최대 약 0.693보다 크고,
클래스 확률 이동 cap 1도 가능한 최대 변화와 같다. 두 설정은 사실상 해당
안전 cap을 비활성화한다. 실제 평가에서도 cap 발동은 0건이었다.

Residual이 지나치게 확신하는 오답을 만들었다는 신호다.

full에서는 큰 scale이 실제로 유효했다. 반대로 limited에서는 계열 적중률만
올라가고 세부 구종 간 구분과 확률 품질이 크게 나빠졌다. 같은 tier boost를
공유시키는 것이 V7.5의 핵심 실패 원인이다.

## 판단

- V7.5 전체 설정은 기각한다.
- full tier에 scale을 더 주는 방향은 추가 검토 가치가 있다.
- limited tier는 V7.4의 4배도 이미 TVD를 악화시켰고, 6.372873배에서는
  Log Loss와 Macro F1까지 무너졌다.
- 다음 실험은 cap을 더 키우지 않고 `full=6.372873`, `limited=4`처럼
  tier를 분리하는 것이 가장 직접적이다.
